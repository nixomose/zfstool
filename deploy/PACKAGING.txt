zfstool packaging notes
=======================

API server (systemd)
--------------------
- Install binary to /usr/bin/zfstool.
- Deb/RPM packages install deploy/zfstool-agent.service as zfstool-agent.service
  under the distro unit directory (not enabled by default). The unit runs
  `zfstool server`.
- systemctl daemon-reload && systemctl enable --now zfstool-agent
- Socket path defaults to /run/zfstool/agent.sock (RuntimeDirectory=zfstool).
- For remoting, run `zfstool web` separately (after the API server) and
  SSH-forward that port (see README Remoting). Optional: add
  -http 127.0.0.1:8787 to ExecStart for API-only TCP.

Web
---
- Start the API server first, then:
  zfstool web -listen 0.0.0.0:8787 -agent-socket /run/zfstool/agent.sock
- Loopback clients: no HTTP auth.
- Remote clients: set ZFSTOOL_WEB_USER and ZFSTOOL_WEB_PASSWORD (or ZFSTOOL_WEB_BCRYPT_HASH), or build with PAM support when added.

GUI / default command
-----------------------
- Running `zfstool` with no subcommand starts an **in-process API server** (unless you pass
  `-agent-socket` / `-agent-url`), a **loopback HTTP server** for the bundled UI, and
  a **native WebKit window** (via `webview`) when built with **CGO_ENABLED=1** plus
  GTK 3 and **WebKit2GTK 4.1** dev packages on Ubuntu 24.04+ (`libwebkit2gtk-4.1-dev`;
  `make deps`). Ubuntu 22.04 uses 4.0 — see `third_party/README.md`.
- Deb/RPM packages install `zfstool.desktop` and hicolor icons (`Icon=zfstool`) so
  desktop environments (XFCE, GNOME, …) show the branded launcher/window icon.
  The native binary also embeds the icon for unpackaged/local builds.
- With **CGO off** or **`-tags browser_gui`** (or **`GOFLAGS`** containing `browser_gui`),
  the same stack runs but the UI opens in your **default browser** instead of that window.
  **`make build` clears `GOFLAGS`** so a global setting does not accidentally pick the browser.
- With no `-agent-url` or `-agent-socket`, the GUI always runs an in-process API server on a
  private socket and stops it when the GUI exits (`ZFSTOOL_SOCKET` does not apply to the GUI).
- `zfstool gui` is the same as the default.
- `zfstool server` and `zfstool web` are explicit daemon modes (API server, then web front-end).
- `make build` uses CGO=1 and links GTK (needs libgtk-3-dev). `make build-browser` is
  browser UI with CGO on; `make build-headless` uses CGO=0.

Remote desktop
--------------
- On ZFS host: zfstool server, then zfstool web -listen 127.0.0.1:8787 …
- On workstation: ssh -L 8787:127.0.0.1:8787 user@zfs-host
- Open http://127.0.0.1:8787/ or zfstool gui -agent-url http://127.0.0.1:8787

Dependencies (runtime)
----------------------
- zfs / zpool (OpenZFS userland matching kernel module)
- optional: smartctl for disk JSON
- optional: journalctl or dmesg for kernel log snippet

Build
-----
- Go module: github.com/nixomose/zfstool (e.g. go install github.com/nixomose/zfstool/cmd/zfstool@latest)
- make deps           install OS packages for make build (apt/dnf/yum/zypper/pacman); `make build` runs this automatically if GTK/WebKit are missing
- make deps-headless  install Go only, for make build-headless
- make deb-deps       install packages for make deb (Debian/Ubuntu apt only)
- make rpm-deps       install packages for make rpm / make srpm (dnf/yum; zypper for rpm on openSUSE)
- make build           (native GTK; CGO_ENABLED=1)
- make build-headless  (CGO off; browser UI)
- make build-browser   (CGO on, -tags browser_gui; browser UI)

Debian (.deb)
-------------
- Build deps: debhelper-compat (= 13), golang-go (>= 1.22), gcc, pkg-config,
  libgtk-3-dev, dpkg-dev; runtime: libgtk-3-0, zfsutils-linux.
- From repo root: make deb   (or: ./scripts/build-deb.sh)
- Installs .deb in parent directory (..).

RPM
---
- Build deps: rpm-build, golang >= 1.22, gcc, gtk3-devel (pkgconfig gtk+-3.0),
  systemd-rpm-macros; git for the source tarball.
- From repo root: make rpm   (or: ./scripts/build-rpm.sh)
- Binary RPM under build/rpm/RPMS/<arch>/; override version: make rpm RPMVER=0.2.0 RPMREL=1
- Source RPM: make srpm
